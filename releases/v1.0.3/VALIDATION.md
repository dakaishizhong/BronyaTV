# BronyaTV 1.0.3 网络接收与播放诊断

历史交付版本：1.0.3。沿用同一包名和发布签名，可覆盖安装 1.0.2 并保留登录。版本号 1.0.3 / versionCode 4；最低 API 23。

SO_RCVBUF 手动设置会关闭 Linux 该连接的接收缓冲自动调节，并受全局上限约束。无 root 应用可以提出每条连接的建议值，却不能修改 tcp_rmem/rmem_max 等系统上限。系统自动模式同样慢时，继续放大应用建议值并不能解决全局上限。本版增加独立 TCP 连接，让多条连接共同承载在途数据。单条连接的广告窗口仍由系统决定。

首次从旧版升级会将手动接收值恢复“系统自动”，之后仍可重新手动选择。新的默认分段接收为单连接；可选择 4 路或 8 路。改变后退出播放并重新打开同一个片源，观察初始缓冲阶段的速度，以及相同播放位置是否流畅。

## 多连接实现

- 设置可选单连接 / 2 / 4 / 8 路；多路模式使用 HTTP/1.1，确保并发请求使用独立 TCP 连接。
- 先校验一段 206 响应，再并发预取后续 Range；有序交给 Media3，不改变媒体格式或创建转码会话。
- 校验 Content-Range 起止位置、文件总大小和每段长度；服务器提供 ETag/Last-Modified 时保持一致并发送 If-Range。片源变化或错误位置时停止合并。
- 第一段未支持 Range、没有合法 Content-Range 等情况，回退标准单连接；保留 401/403/404/410 状态用于既有地址刷新和 original 文件恢复。
- 每段 64KiB 至 2MiB；总预取容量不超过 16MiB、应用最大堆的八分之一、剩余堆的八分之一中的最小值。低内存或预算不足时使用单连接。Media3 播放内存另按既有安全策略限制。
- 保留原请求地址及服务商签名参数，不直接把服务器认证头发送给重定向后的 CDN。后续分段仍经过认证头跨域移除规则。
- 退出、拖动或重建播放器时取消分段任务并释放内存。没有磁盘缓存或后台下载。

多连接效果取决于服务端、链路和设备。服务商若限制连接或请求次数，可回到单连接；实际吞吐取决于服务端、网络和设备。

## 新诊断

普通播放菜单 →“播放诊断详情”，无需启用隐藏调试。可用遥控器滚动，支持刷新和复制。

- 片源容器、视频 Profile、声明的位深/帧率/总码率/大小。
- 实际视频、音频输入的 MIME、codec 字符串、分辨率、位深/HDR、采样率和声道数。
- 实际 MediaCodec 名称及系统声明的硬件/软件属性；系统没有明确声明时不猜测。
- 输出帧率、渲染/跳过/丢弃帧、音频欠载、帧处理偏移和缓冲趋势。缓冲状态按秒观察，短于采样间隔的状态变化可能漏计；缓冲累计排除首次启动，含拖动后缓冲。
- 实际接收速度、近 5 秒均值、近 30 秒峰值、累计接收量和距最近数据时间；包含预取及等待。缓冲充足停取流时速度可能为 0。
- 接收方式、预取/播放内存、SO_RCVBUF 最近连接的实时系统报告值。它不是 TCP 广告窗口，也不是所有连接缓冲的总和。
- 视频取流 HTTP 协议、远端 IP、DNS/连接/TLS/请求至响应头时间、状态、Content-Type、Content-Range、重定向/请求失败/活动请求数和同时连接峰值。响应头时间包含服务端处理等，不能代替 RTT；字幕请求不会覆盖视频取流摘要。
- 网络接口、可读取的 Wi-Fi/以太网链路信息及内核 TCP 配置。无权限或系统未提供时明确显示受限。
- URL 用户信息、全部查询值、片段均隐藏，避免复制服务器 Token 和签名。

## 验证

- 35 项单元测试通过：原有 25 项，加 8 项分段完整性/并发/取消/故障/重定向认证测试和 2 项速率与地址遮盖测试。
- 同一按连接限速的 4MiB 夹具，最终测试记录单连接 1327ms、4 路 408ms，同时 TCP 连接峰值为 4；字节完全一致。具体记录以 `network-fix-1.0.3/unit-tests/TEST-tv.ember.client.ParallelRangeReaderTest.xml` 为准。该夹具只证明独立连接可突破每连接限速。
- Android TV 13 / API 33：25 项设备测试通过，0 失败/跳过。包括 4 路 MP4 的音轨/字幕/生命周期、8 路 MKV 字幕、4 路 410 恢复、Range 被忽略时回退、65 秒拖动后继续播放及源格式/实际解码格式显示；既有登录、启动、缓冲、重连测试继续通过。
- Android TV 11 / API 30：2 项通过，0 失败/跳过。HEVC 10bit 片源与官方 Emby 4.10.1.0 三种版本均以 4 路设置实际播放。API 33 模拟器缺少该 Main10 解码能力，因此在支持该样本的 API 30 验证。
- Debug/Release lint 无错误；Release 构建、签名和 zipalign 检查通过。发布签名 SHA-256：`b8418a96c9181475cf64d4ad5e782585e0a54fa683c3d59d864ad1a16666631a`，与 1.0.2 一致。
- 正式包 TV UI：覆盖升级保留登录、4096KB 旧值一次性恢复自动、选择并保留 4 路设置、410 的 stream.mp4 恢复 original.mkv、READY 播放、诊断详情/复制和遥控器滚动。最终结果见 `network-fix-1.0.3/release-ui-smoke.json` 与截图。
